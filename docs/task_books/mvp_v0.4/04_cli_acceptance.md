# 04 · CLI 与工程验收

前置：03 闭环通过。复用现有 CLI，不开发 Web 界面。

## CLI

增加 `--rag` 显式开启和 `--knowledge-dir` 指定本地受审核知识目录，默认关闭；不读取任意远程链接，不自动下载模型。路径/格式错误给出安全提示，运行模式与回退状态明确可见。不要把知识读取错误伪装成启用成功。

装配时注入 KnowledgeEngine；现有未开启 RAG 的构造和 `--demo` 继续兼容。`--demo --rag` 使用明确标注的演示知识，不冒充真实审核或模型效果。

确认前展示“知识仅辅助明确委托项”的说明，但不改变现有确认哈希算法：用户确认的是已展示的 Intent 与委托范围；检索后仅在该范围内实现。生成后显示本次采用/回退/复用、受影响路径与来源 ID，能够根据 Bundle 查到完整来源；不要说用户确认过其未见的具体知识选值。

## 集中验收

开发时跑局部测试；01～04 完成后运行一次全量 `uv run pytest -q` 与 `git diff --check`，失败按具体原因修复再验证。全部离线，不执行 smoke 或真实图片批次。

必须有 Fake 端到端覆盖：

1. RAG 关闭时完整旧流程。
2. 用户委托光线/景别/景深后，受审核知识影响至少一个具体实现；记录可追溯。
3. 用户明确指定与 PIN 的字段不变；知识给出其他建议也不能覆盖。
4. 无知识命中、draft-only、损坏语料：状态透明且安全回退。
5. 反馈修改、重新确认、Realization carry/失效正确，旧 Artifact 不覆盖。
6. 图片 Provider 失败后 retry 复用原 Prompt，查询调用数不增加。
7. 知识版本更换：新选择记录新版本；已有实现和历史生成可重放。

知识尚未人工批准时，第 2 项用测试审核数据证明工程功能，并明确生产验收未完成。README 只更新项目架构、简短用法与真实状态，详细计划保留在本目录。

## 停止点

交付 v0.4 工程预览、实际测试与内容审核清单。未经额外评测启动指令，不自动花费图片/API 预算。正式运行需代码/语料身份可复现，当前未提交成果不能被伪装为干净版本。

知识库质量、检索质量和最终图片质量是三个不同结论。离线安全测试通过只允许声称工程可用，不允许声称优于无 RAG 或正式发布成功。
