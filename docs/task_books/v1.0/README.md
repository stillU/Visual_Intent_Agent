# v1.0：最小交付收敛任务书

日期：2026-09-17。状态：计划，尚未实施。本轮仅静态检查并编制任务书，不修改实现。

实施进展（2026-09-18）：Step 01～04 已静态实施，本轮同样未运行测试或验证；交接见 [v1_0_handoff.md](../../handoffs/v1_0_handoff.md)，候选交付说明见 [v1.0.0rc1.md](../../releases/v1.0.0rc1.md)。

用户最新裁定：快速推进 v1，不进行测试和运行验证。因此本任务不要求补跑 v0.6 正式评测，也不把任何未经执行的检查写成通过。建议先以 1.0.0rc1 候选交付，不能将版本号视为已验证稳定性的证明。

## 1. 目标与范围

将现有产品整理为入口明确、配置清楚、文档一致、限制透明的 v1 候选交付。保留自然语言需求、澄清确认、确定性提示词编译、图片生成、反馈修改、SQLite 追溯和可选本地 RAG。

不新增 Web UI、部署平台、多模型、向量库、在线知识采集或额外 LLM；不改变领域合同、数据库 Schema、PIN/确认、重试行为、知识候选或已批准语料。不把 v0.6 的评测工具当作产品日常入口。

静态基线见 [v0.6 检查记录](00_v0_6_static_review.md)。v0.6 当前只有离线准备与 Fake 执行器交付，不是完整的真实效果评测。v1 交付整理与该评测任务分开管理，不能改写历史状态。

## 2. 执行顺序

| 步骤 | 最小任务 | 交付物 |
|---|---|---|
| 01 | 统一应用版本与展示 | 元数据、包版本、CLI 展示一致 |
| 02 | 整理配置与现有启动方式 | 无凭据模板、准确的源码运行说明 |
| 03 | 精简项目介绍、独立使用说明 | README、使用指南、候选交付说明 |
| 04 | 静态收敛与交接 | 改动列表、未执行项、已知限制 |

默认一个 Agent 顺序完成，指令见 [Agent 派发入口](AGENT_DISPATCH_PROMPTS.md)。本书只授权后续获派 Agent 做这些最小变更，不要求在本对话立即实施。

### Step 01：版本一致性

建议应用版本采用 1.0.0rc1，明确“候选交付、本轮未验证”。同步 pyproject.toml、本项目在 uv.lock 中的版本项、visual_intent_agent 包版本及现有 CLI_VERSION；CLI 尽量引用包版本，避免多处硬编码。不要升级依赖或重写锁文件中的第三方包。

仅修改当前展示和模块说明，不批量替换历史文档的 v0.2/v0.3/v0.4 字样，不把知识目录 v0.5 或评测协议 v0.6 改名为 v1。应用、知识快照、协议和数据库 Schema 是不同版本。

如果当前文件已被他人更新，先阅读实际内容再做最小修改；不覆盖其他 Agent 的成果。不创建 Git tag，不因版本更新自动提交推送。

### Step 02：配置与启动

新增 .env.example（若已有则复用），只列当前 Settings 真正支持的变量：Provider endpoint/API key、LLM/图片模型、超时/重试、数据库与输出目录。必填凭据留空，不放真实值，不读取或覆盖 .env/api.md。

沿用现有 Python 3.12+、uv、源码模块入口；不新增打包体系或服务进程。说明从仓库根目录安装依赖和使用已有 --demo、--rag、--knowledge-dir、--db、--output-dir、--version 参数。

必须讲清：

- --demo 是脚本式 Fake 演示，不代表真实语言理解或图像质量；演示与真实数据库默认位置不同。
- 真实模式需要配置且可能收费；日常 CLI 不具备 v0.6 评测层预算守卫，不能误称已有全局消费限额。
- RAG 仍默认关闭；单独 --rag 默认读取 v0.4 草稿目录，选择已批准语料需显式指定 knowledge_base/v0.5。
- --demo --rag 用内置测试夹具，不等于生产语料；不能与外部 --knowledge-dir 混用。
- 不自动确认、不绕过 PIN；生成/编译失败的可重试条件按现有实现描述，不新增自动重试承诺。

不为了简化命令改变 RAG 默认行为，不把配置示例中的模型别名说成已核实的官方模型版本。本批只写说明，不执行安装或启动。

### Step 03：文档整理

根 README 保持简洁：项目目标、核心架构、业务数据库与可选知识库的关系、候选交付状态、少量入口链接。操作流程和长参数说明迁入 docs/USAGE.md；保留原有有用信息，修正移动后的相对链接，不把任务步骤重新塞进 README。

新增 docs/releases/v1.0.0rc1.md，至少包括：

1. 实际交付范围及版本标识，本轮仅静态整理、未测试或运行验证。
2. 已批准知识快照不变，正常数据库与历史语义不变；“未修改”不等于本轮已证明无回归。
3. v0.6 真实执行入口尚未实现可用调用，不能只改授权布尔值就运行；盲评/收益结论缺失。
4. COCO-CN 许可仍待确认，不纳入新增内容；v0.5 的遗留状态保留。
5. 升级前退出写库进程、保存完整数据库备份及适用的 WAL/SHM、输出和对应代码/语料版本；不覆盖数据库或替用户执行备份/迁移。
6. 源码项目运行方式、工作区未提交状态、尚无正式发布身份；不声称已有 pip 包、容器或独立安装程序。

可对 docs/ARCHITECTURE.md 的当前状态做最小更新，但不重写历史 ADR、审核决定、冻结配置或已有评测结果。

### Step 04：静态收敛与交接

只阅读代码与文档，确认描述没有超出实现；不运行测试、校验器、CLI、Fake 演练、安装、构建、哈希复算或真实服务。任何历史测试数字必须注明“前序报告记载，本轮未复跑”。

产出 docs/handoffs/v1_0_handoff.md：实际修改范围、保持不变的合同、静态发现、未执行项、配置/数据/评测遗留问题以及当前交付状态。索引链接到新交付说明，旧报告保留原时间与结论。

## 3. 交付条件（非运行验收）

- 计划中的版本/展示/配置/文档改动已落地且可供阅读。
- 产品入口与评测入口分开，RAG 和正常数据库职责准确。
- 已批准语料、冻结评测文件和用户数据库未改动。
- 明确写出“本轮未测试、未运行验证”，不填写通过数量或稳定性保证。
- 没有真实调用、费用、凭据读写或未经授权的提交推送。

满足以上条件只能称“v1 候选交付整理完成”，不能称已验证稳定版，也不能声称 v0.6 全部完成。今后若用户需要稳定发布或效果结论，再单独决定验证/评测范围；本任务不自动启动这些工作。

## 4. 停止与范围控制

发现需要改变运行时架构、确认/PIN/数据库、已批准知识或付费服务才能解决的问题，记录证据并请求决定，不为了赶 v1 扩大范围。版本展示与文档可以先独立交付，不伪装未解决项已经修复。
