# Step 03：获授权后真实运行与盲配对评审

前置：Step 01/02 完成，G1 精确批次/预算/模型/评审安排获用户确认，正式代码身份 clean、冻结文件一致。否则停在准备完成，不运行真实服务。

## 运行

逐对执行，默认低并发以减少预算和状态复杂度。每次请求前校验剩余预算，按协议记录时间、失败和成本。发现安全违例、身份/哈希漂移或达到费用/尝试上限立即暂停，保留已有结果。

同一冻结协议内的续跑遵守幂等性，不覆盖输出或选择性丢弃差图；用户更改语料、Prompt 逻辑或模型后创建新协议/run，不把变更前后结果合并成一次公平比较。

## 盲评材料

只为双方均有有效图片的对生成随机左右展示；side→arm 映射单独保存，评审页面/文件名隐藏知识开关、候选来源与采用标签。显示用户原始要求、已确认约束及明确委托范围，避免评审人自行发明需求。

冻结每对的随机位置映射、图片哈希和元数据；评审人在解盲前提交胜/平/负、用户约束遵守及简短理由。至少一名真实评审人，记录身份；有多名时预先约定分歧处理与一致性指标，不事后挑选有利评审。

单侧失败不伪造成差图参与视觉偏好，记入失败/完成率；损坏图片、拒绝输出和缺失评分分别记录。评审人无法盲评或已知标签时明确披露。未提交评分不得由 Agent 补造；不引入额外付费模型裁判。

## 完成与交接

写 docs/handoffs/v0_6_step_03_handoff.md：批准范围、真实消耗、计划与完成对数、失败/未知请求、评分覆盖率及是否解盲。未运行/部分运行/待人工评审必须分开，不能写成评测通过。
