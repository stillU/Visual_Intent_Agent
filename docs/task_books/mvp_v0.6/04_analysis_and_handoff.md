# Step 04：结果分析、收敛与交接

## 分析

按冻结协议计算总体与三类分层结果：有效双图的胜/平/负与净胜率、以独立上下文为单位的区间、全部计划请求的成功/失败/未知与成本。重复图不是更多独立语义样本；未采用 RAG 的对不能被从总体中删除，采用子集分析只能作为补充。

区分“条件适用但未召回”“有推荐但消费端拒绝”“实际采用且 Prompt 改变”“采用与基线恰好同值”。报告最终采用而非只报命中率。不做 post-hoc 样本剔除或阈值修改来制造成功。

三种可接受输出：

- 支持收益：符合预先确认的质量、约束、完成率和成本阈值，仍限定到实际样本/模型/规则范围。
- 未见收益或退化：如实报告，不为证明 RAG 有用而现场扩大知识库。
- 证据不足：样本少、区间跨零、评分缺失或未知模型波动等，说明原因；增加预算/样本需另获批准。

发现内容问题只整理待审核提案；原 v0.5 快照不改。若要试改版，应新建语料版本、重新批准及新评测，不在同一保留集上反复调整后仍称首次验证。

## 离线回归与交付

运行新评测层定向测试及全量默认离线回归，保留普通数据库、旧历史和 retry 测试。执行 git diff --check。真实图片成果放独立 run 输出目录，不提交凭据/用户数据库/不明权利的图片。

每步写 docs/handoffs/v0_6_step_XX_handoff.md；最终写 docs/handoffs/v0_6_release_handoff.md，列出：

1. 代码、协议、样本/标注、语料、模型和配置身份，真实执行授权入口。
2. 工程测试与可复现命令；真实执行/盲评/分析各自完成度。
3. 样本来源、许可、分组、污染风险和未支持语义。
4. 样本分母、全部失败、评分覆盖率、区间、成本及原始证据定位。
5. 是否达到预先阈值；未达到时不伪称质量通过。
6. v0.5 COCO-CN 遗留状态、v0.6 已知限制、下一步选择。未获授权不启动后续版本。

整体完成指按批准范围完成工程、运行、真实评审和诚实分析，不要求 RAG 必须获胜。若停在 G1，仅交付“离线准备完成”，不能把空报告视为完整 v0.6。
