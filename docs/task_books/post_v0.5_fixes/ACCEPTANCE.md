# v0.5 收尾验收与交接

## 执行顺序

1. 记录 HEAD、dirty 状态、已有审核决定、生产快照与五份提案哈希；确认离线测试排除 smoke。核验失败不能通过改期望值解决。
2. F1 先补“无暂存依赖”回归，再归档并变更读取位置。
3. F2 复用已有测试建立当前验收清单，补缺失断言，整理历史说明。
4. F3 隔离许可待定内容，准确记录状态，不代替用户决定。
5. 定向测试通过后集中全量离线回归，验证可移交性。

## 两种必测环境

### 原工作区

执行 uv run pytest -q、提案校验工具和 git diff --check。记录实际退出码、数量、环境与未执行项；不复制旧测试数字。优先复用已安装依赖，不因缺依赖自动升级无关组件。

### 不含本机暂存的隔离副本

创建专用临时目录，按显式白名单复制当前可交付代码、配置、tests、knowledge_base 及所需文档/审核归档。工作区未提交，不能只复制 HEAD 或仅用 git archive 代表当前成果。排除 .git、.env、api.md、data、outputs、用户数据库与缓存，不能打包整个工作区。

复用已有测试环境的 Python，从副本根运行测试和提案验证工具，确认导入来自副本而非原工作区。优先运行全量离线测试；至少覆盖发布守卫、当前三十场景、生产知识采用闭环、数据库兼容与提案校验。未跑全量时明确覆盖边界。

副本应无 data/、无需补下载，且五份归档和测试输入完整。不得移动或重命名真实 data 目录模拟环境。新增归档/fixture 应通过 Git 忽略检查，交付清单列出尚未提交的新文件。
