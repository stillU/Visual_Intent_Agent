# Step 01：开放文本准备与可追溯样本

## 输入与范围

先读取 [资源包](../rag_resources/README.md)、[数据说明](../rag_resources/DATASETS.md)、[固定来源清单](../rag_resources/sources.lock.json)。沿用其中官方固定版本、哈希与许可限制，不重复维护另一份矛盾的来源表。

本步准备工程输入，不运行图片生成、官方评分器或正式评测。开放 prompt 不等于本项目的 Intent/PIN/委托标注。

## 执行

1. 依资源包将原始文本与许可下载到独立 `data/staging/rag_resources_20260916/`；已有内容先核验再复用，不覆盖。七个已锁定文本文件逐一验证原始字节哈希、大小和非空行数。校验失败停止该来源，不能用改期望哈希的方式过关。
2. COCO-CN 按固定托管 revision 获取归档，先安全检查路径/链接/解包大小，再确认内部许可与字段；保存新算的哈希到本次下载记录，不把此前 metadata_verified 冒写为历史已下载。
3. 依资源包规则准备 70 条原始文本（GenEval 20、CompBench 30、COCO-CN 20），记录来源、语言、原始 ID、分组、支持范围和丢失风险。数据不足或访问失败允许交付可用部分并标缺口，不以自编中文样本冒充 COCO-CN。
4. 按父样本/同图/相同原文组划分开发与保留池。使用来源包固定哈希排序，以组为单位约 70% 开发、30% 保留，记录实际数与分组算法；不要求每个子类精确比例。保留池本版只校验格式与来源，不用于知识选择、关键词修改或回归断言开发。
5. 从开发池制作项目派生工程样例，必要的确认、PIN、委托状态必须显式标注为项目添加；不把 benchmark 元数据伪装为用户表达。暂存标注不是新增运行时 Schema。

若自动化确有必要，只增加一个小型标准库准备工具；参数有大小/超时限制，不执行下载内容，不加载远端代码。对解析、哈希失败、稳定抽样及分组不泄漏做离线测试。没有必要不引入依赖或数据平台。

## 交付与验收

- 暂存目录中的原始文件、许可、下载记录、样本/分组清单；原始文件不清洗改写，派生物独立保存。
- 可重建的小型清单/工具与必要测试可纳入代码；大归档与照片不入 Git，不改已有忽略规则以外的无关内容。第三方文本需先确认允许再分发。
- 交接列出每个来源的成功/失败、哈希、实际样本数、许可剩余事项、开发/保留组数及重建命令；不声称正式测试集已经冻结。
- 来源暂缺不要求联网绕过限制；补齐前本步骤标记部分完成。Step 02 可继续，不需要等待下载。
