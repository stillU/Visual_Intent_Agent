## F1 · P1：修复 Preservation 的比较基准

定位：`evaluation/metrics/prompt.py::evaluate_preservation_r1`；相关测试在 `tests/evaluation/test_r1_metrics.py`、`tests/evaluation/test_r1_runner.py`。

### 已复现的问题

`pending_changed` 仅在成功构造比较对时清空。首次生成没有前置 Prompt，初始 SET 的字段因此一直留在集合里，后续应保留的主体、风格等被误当作“本轮合法修改”排除。

最小场景：

- t1：生成 `cat watercolor`，`changed_paths` 为主体与风格。
- t2：只允许修改光线，要求保留 `cat` 与 `watercolor`，实际生成 `dog watercolor`。
- 现状：`not_applicable`、零比较对；正确结果：一个比较对，保留一组、丢失一组，得分 0.5。

审查还用当前 r1 标注构造离线输入，12 个包含多次预期生成的案例均得到零比较对。这不是模型运行结果，而是评分函数的确定性复现。

### 最小实现

1. 只累计上一个有效 Prompt 之后、当前有效 Prompt 之前及当前轮的合法修改路径。
2. 当前轮有 Prompt 时，先完成可用的比较，再无条件将其设为新基准并清空累计路径；是否存在保留标签、是否构成比较对均不能阻止清空。
3. 当前轮无 Prompt 时，继续累计路径；正常澄清仍不算内容丢失。保持已有失败计数与未知值语义。
4. 仅修 r1 实现；旧 v1 评分函数与旧结果保持不变。

### 必须新增的回归

- 上述 `cat → dog` 场景准确得到 0.5；完整保留得到 1.0。
- 首次生成前经历多个澄清轮，初始字段仍能进入后续保留评分。
- 两个有效 Prompt 之间存在无 Prompt 的合法 SET/CLEAR：该路径仅在本次比较被排除。
- 中间有效 Prompt 无保留标签，仍更新基准并清空累计路径；下一轮不能沿用更早的排除项。
- 通过 Runner 构造真实标注到指标的离线集成用例，避免只在手工省略初始 `changed_paths` 的输入上通过。

## F2 · P2：保留级联阻断轮的完成率分母

定位：`evaluation/runner.py::_l3_metrics` 附近构造 `PromptSequenceTurn` 的逻辑，以实际函数名为准；`evaluation/metrics/prompt.py::evaluate_generation_completion`；相关测试在 `tests/evaluation/test_r1_runner.py`。

### 已复现的问题

Runner 为 `blocked` 轮设置 `expected_prompt=None`，完成率只统计 `expected_prompt=True`，于是级联阻断的预定生成轮从分母消失。现有合成案例原本预期生成两次，记录的分母却只有一次。

“一个独立故障根因”与“多个未完成的生成目标”是不同统计对象，不能用根因去重缩减完成率分母。

### 最小实现

1. r1 的 `expected_prompt` 始终由冻结标注派生，不因 `blocked` 改成 None；旧 v1 分支不改。
2. 完成率分母包含所有标注为 `ready_and_generate` 的轮，实际未产出 Prompt 的阻断轮计未完成。
3. 保留 `blocked_by_prior_failure`、`blocked_by_turn_id` 与首次根因；不为每个阻断轮再伪造一个异常，不执行原本已阻断的调用。
4. 正常澄清、接受、不要求生成的轮次仍不进入分母。当前指标是 Prompt 产出完成率，不借此宣称图片生成成功率，也不顺带改造指标含义。
5. 核查汇总输出能够区分根因失败与级联阻断，必要时添加兼容计数；不得覆盖旧报告或自动重算历史批次。

### 必须新增的回归

- 预期生成两轮，首轮失败、第二轮 blocked：分母 2，产出 0，未完成 2，独立根因仍为 1。
- 预期生成三轮：成功、失败、blocked：完成率为 1/3，不能是 1/2。
- 首轮是预期澄清但发生失败，后续预期生成轮 blocked：完成率为 0，不是“不适用”。
- 正常澄清与终局接受不计入分母；A/B 使用同一预期生成口径；旧 v1 回归不变。

## F3 · P2：修复 CLI 对历史 Prompt 的错误重试提示

定位：`visual_intent_agent/cli.py::SessionApp.can_retry_generation` 与 `run_repl` 的 FAILED 分支；相关测试在 `tests/cli/test_cli_e2e.py`。

### 已复现的问题

第一轮成功生成 → 反馈修改 Intent → 重新确认 → 第二轮编译失败。此时旧 Prompt 仍存在，但它绑定的确认已失效。CLI 仅检查历史 Prompt 是否存在，持续显示“可用同一 Prompt 重试”；实际 retry 被 `generation.no_valid_confirmation` 拒绝。

### 最小实现

1. 只读查询最新已落库 Prompt，并复用 Repository 现有确认有效性判断；不存在或绑定确认失效时，不提示可重试。按现有模型读取 `based_on_confirmation_id`，不自行复制确认判定规则。
2. FAILED 分支分别说明“无可复用 Prompt”与“历史 Prompt 已过期”，避免将后者错误描述成从未编译。沿用当前退出后新建会话的处理，不新增会话恢复机制。
3. 底层 `GenerationPipeline.retry` 的 FAILED 状态与确认校验必须保留；CLI 的预检查不是授权，预检查后发生状态变化仍由底层拒绝。
4. 不回退生成旧图，不自动重新确认，不重新 compile，不伪造 generation ID，不放宽 PIN、Revision 或 Artifact 约束。

### 必须新增的回归

- 第一轮成功、修改后第二轮编译失败：旧 Prompt 存在但不可重试，显示过期原因；输入 retry 不触发图片 Provider，仍可退出。
- 首轮编译失败且无 Prompt：准确提示不可重试，不崩溃。
- 第二轮成功编译、图片 Provider 失败：允许重试并复用第二轮 Prompt，而非第一轮。
- 预检查后确认失效：底层仍拒绝，不调用图片 Provider。
